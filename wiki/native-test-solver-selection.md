# Native tests depend on which Z3 Dafny selects

Status: current; checked 2026-10-27 on `1de66ec5a` and `pin/2026-10-27` (resolved at `16e825ccd`). Originating plan: [pin test repair](../plan/2026-10-27-pin-test-repair.md).

Dafny looks for `z3/bin/z3-<DafnyOptions.DefaultZ3Version>` next to the loaded `DafnyCore.dll` (`DefaultZ3Version` is `4.16.0` in `Source/DafnyCore/DafnyOptions.cs`) and otherwise falls back to the first `z3` on `PATH`. The test projects copy `Binaries/z3/**` (both `z3-4.12.1` and `z3-4.16.0` on this machine) into their output directory, so a normal build selects 4.16.0, while a build without that directory selects the system `z3` (4.8.12 here).

Five tests give different results by selected solver, on the unchanged origin base `1de66ec5a` as well as on the branch: `ContractQueryTests.ProofOnlyQuantifiersRetainOriginalAssertionAndDefinedness("exists k:int :: result == 2*k")` (needs a witness proof; fails only on 4.16.0), `ContractWitnessQueryTests.ConcreteConcatenationRetainsNativeTarget("!(exists a:seq<int> :: [1,2] == a + a)")` (exceeds its 3 s deadline on 4.12.1 and 4.16.0), and in `DafnyDriver.Test` `ClauseDependenciesTests.ClassifiesEveryBucket`, `ClauseDependenciesTests.UncertifiedDependencyKeepsCalleeClauseUnchecked(3, ...)` and `InitialAdmissionTests.ScalarClosedCalleeUsesOriginalSources(2, False)`. With the 4.16.0 file hidden from the test output directory all of them pass at both revisions. Under 4.16.0 the opaque-dependency bucket reports callee violations where 4.8.12 leaves the clause unchecked, which is a solver-result difference, not an effect of the branch.

Decision (2026-10-27): the bundled `z3-4.16.0` is the reference solver for these tests, and its results define the expectations. At `16e825ccd` the Driver `ContractRuntime` filter (306 tests) and the TestGeneration `Contract|Pbt` filter (1061 tests) pass with the default selection. The tests now assert 4.16.0 behavior: the opaque-dependency callee clause is refuted for its whole bucket (`OpaqueDependencyViolatesCalleeClause`, `ClassifiesEveryBucket` with 4 callee violations and 8 unchecked); the valid existential callee clause is unchecked by `closed_query_timeout` (`ScalarClosedCalleeTimeoutLeavesClauseUnchecked`); the positive existential `exists k:int :: result == 2*k` retains its assertion with reducer decision `Residual` (`ProofOnlyPositiveExistentialStaysResidual`); the `!(exists a:seq<int> :: [1,2] == a + a)` concatenation case was deleted as deadline dependent. No timeout, deadline or production code changed.

Use this when a native contract test fails only in an environment lacking `z3-4.16.0` (for example the system 4.8.12 fallback): the expectations above assume the bundled solver, so those cases are expected to differ there, not to indicate a source regression. Compare against the base revision with the same `Binaries/z3` before attributing a failure to a source change.
