# PBT random source bounds and Unicode scalar intervals

Status: current; locally checked 2026-10-20 on native base `10dca3ba4a2909c11299176440401fc31413b53d` plus the [originating plan's](../plan/2026-10-20-pbt-random-api.md) working-tree changes. Independent integration review and the full-source hash-pin update are parent-owned.

`Source/DafnyTestGeneration/ContractTesting/Library/PbtRuntime.dfy` exposes the generator-facing API. `Source.Size()` now guarantees `2 <= s <= 32`; the C# implementation computes `min(2 + ordinal / 4, 32)` for nonnegative sample ordinals. Size queries do not advance the random stream. The runtime `Source(ulong seed, int ordinal)` constructor supports direct deterministic callers and rejects negative ordinals; the existing process-command-line constructor delegates through it.

`Dafny.Rune` represents Unicode scalar values, so U+D800 through U+DFFF cannot be returned even when valid endpoints straddle that interval. `Source.Char` samples the compressed valid interval with one integer draw, then adds `0x800` to ranks at or above `0xD800`. This keeps both inclusive endpoints reachable and avoids attempting to construct an invalid rune. All character ranges wholly below or wholly above the surrogate gap retain their previous exact integer draw path; other random methods retain the existing SHA-256 stream. Crossing-gap draws intentionally change because the previous implementation could throw on valid API inputs. The existing modulo-based sampling behavior is otherwise unchanged; these checks establish no distribution claim.
