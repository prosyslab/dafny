# Resolved function body visibility

Status: local implementation and fresh independent final-source checks passed on 2026-10-19.
Originating plan: [resolved function body visibility](../plan/2026-10-19-function-body-visibility.md).
Revision: isolated worktree based on `bef89d224`; focused delivery commit is recorded by the parent integration plan.

`DefinitionAnalysisResult.BodyVisibility` is optional resolved compiler metadata. The camel-case JSON contract is `bodyVisibility` with `isOpaque`, `revealedFunctions`, `revealsAllFunctions`, and `referencedDeclarations`. Span-only results and roots without successfully resolved modules omit it. Existing `dependencies` retains its direct semantics.

`isOpaque` comes from `BoogieGenerator.IsOpaque`, including the opaque keyword/attribute and default opacity options. Names are canonical full Dafny names, unique and ordinal-sorted. `referencedDeclarations` includes the full resolved declaration dependency closure, including declarations outside the requested source set, with root identity omitted. Constructor references name their owning datatype; bound type parameters are not source dependencies. This allows a caller to identify ordinary dependencies through included or frozen wrappers without treating existing direct edges as transitive.

Visibility is deliberately conservative: contracts and bodies of every reachable declaration participate even when only contracts would ordinarily be used. Explicit reveal OffsetMembers, generated reveal calls carrying the resolved `revealedFunction` attribute, and function-targeted typed `fuel` attributes count as possible exposure. Wildcard reveal, malformed reveal targets/attributes, and unmappable relevant declaration identities set `revealsAllFunctions`; this flag is also the conservative unknown-closure signal. A consumer must recheck rather than assume that an unknown closure excludes an edited function. Hiding alone does not expose a body. There are no source keyword/function-name heuristics.

Direct facts are cached by resolved declaration identity within a single analysis call. Closure computation follows `IHasReferences`, explicit function/method call targets, inherited member identities, typed attributes, resolved expression component/result types and normalized type proxies. This includes instantiated subset constraints even though resolved generic syntax nodes drop their original type arguments. Referenced containers do not descend into child members, so unrelated siblings do not contaminate a root. Intrinsic synthesized ArrowTypes with no declaration identity contribute their argument/result types; other missing declaration identities remain conservative unknowns. UserDefinedType traversal uses resolved references and TypeArgs rather than its retained syntactic NamePath. No global/cross-run cache or proof identity is introduced.
